Details: read before relying on it
  • The tests ran on one Python project of 86 files, with three lookup questions, on Claude Haiku 5.5, low effort and Claude Sonnet 5.5, medium effort.
  • The ready brief means pgr prepared the answers before the agent started. The agent had no command to call. The questions suit it: two of the three in each set name the function.
  • The people who built pgr wrote the questions. The second set was written after the first, but the ready brief was written after both had been run, so it is not an untouched test.
  • Open-ended work was not tested: finding a bug, changing code, or exploring a repository the agent was not pointed at.
  • The agents without pgr were run a day before the team tests, so that comparison crosses a day. On the test machine another tool altered some of their reads, which lowered their correct answers, so pgr is compared with them on tokens and turns, not on correct answers.

Finds a definition and its callers

pgr about SomeFunction

Searches code by meaning

Describe a job in words. Get the function that does it.

As the only command an agent had, it read from 14% fewer to 31% more tokens than no pgr, and 6 of 12 runs were fully correct. Its search quality alone is on the Results page.
