Teams of agents

Many agents, one job.

What pgr does when several agents work together, and how far each part has got. Each part says whether it was measured, is available, or is still in development.

The parts

Each agent's tools in its own Linux environment

In the team tests the subagents ran every lookup inside an Ubuntu virtual machine (WSL 2) beside the person's desktop, with the same cost and accuracy as on Windows. The same runs fit in a container per agent as well (see the own-screen item).

Measured

Agents share what they find

One agent files a finding and the next starts from it. On the questions whose answer was a note left by an earlier agent, 15 of 15 note fields were right with the notes and 0 of 15 without them.

Measured

Knowledge kept across conversations

Notes are kept on the user's own disk, per repository or in a shared bank, so a new conversation starts from what earlier ones found. Notes about code that has changed since are marked.

Available

Important information carried over before the context fills

Before a client compacts a long conversation, pgr 0.3.0 saves the important points (the goal, the latest request, the files touched, failures, open to-do items and the decisions the person stated) as notes, and puts them back right after, with hooks for Claude Code and the Codex CLI. Tested on synthetic conversations of both clients and on one real Claude Code conversation; not benchmarked. Skills, plugins and extensions are never compacted: the client loads them again from disk.

Available

An own screen for browser agents

In a test version, each agent gets its own Linux box (a Docker container inside Ubuntu on WSL 2) with its own browser and its own screen, which the person watches in a browser tab while working beside it. It is not shipped yet. Tested on 2026-10-19: three boxes started in 28 seconds, each showed only its own screen, none could see another's files or screen, the engine inside a box gave byte-identical answers to Windows, and each used about 270 MB with a browser open, capped at 1.5 GB and 1.5 processor cores. A tool call through a box adds about 0.1 to 0.2 seconds.

In development
Details: what the team tests show and do not show

The note-sharing result comes from a small set of questions that the builders wrote so that each answer needs a note an earlier agent filed. With the notes, 15 of 15 note fields were right; with none, 0 of 15. It shows that notes are passed on and used. It is not a test that nobody tuned for.

On the ordinary lookup questions of the Results page, a team (Claude Opus 5.5 orchestrating, Claude Haiku 5.5 answering) used 14% to 34% more tokens when its agents shared notes, and no answer got better: 24 of 24 runs were fully correct with the notes and without.
